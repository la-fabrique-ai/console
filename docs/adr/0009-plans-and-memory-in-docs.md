# 0009 — Plans and memory live in docs/ of the project

## Context
The plans were in Linear, which does not work with the other connectors. A separate `plans` repository, Obsidian Sync and several third-party tools were compared on 2026-11-20.

## Decision
Each project keeps in its repository: `docs/context.md`, `docs/index.md` (generated by the engine from the headers), `docs/adr/` and `docs/missions/<ticket>/` (spec, split, closing report). The spec and the split are written on the mission branch and merged with it. Reading by role: Pilot reads the whole project, the Lead and the devs read their mission and the cited decisions. Pilot writes a decision when it is taken with Nicolas; at closing, the Lead writes the closing report and proposes the decisions that came up along the way. A single flow and a single default format; each project can set the locations and the spec template. Linear no longer holds the plans: an import command, per project, copies its documents as Markdown into `docs/` without deleting anything there, then Pilot proposes the context and the decisions to draw from them. Nicolas reads in Obsidian by opening `docs/`.

## Why
A machine that has the code has the plans, remote server included. The spec travels with the code it asks for, and a decision becomes valid when its code is merged.
